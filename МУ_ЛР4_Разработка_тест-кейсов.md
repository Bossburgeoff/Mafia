## 1. Цель и задачи работы

**Цель:** освоить разработку тест-кейсов и чек-листов для проверки программного продукта.

**Задачи:**

- определить объекты тестирования в проекте;
- выделить классы эквивалентности и граничные значения;
- составить 15–20 тест-кейсов с ожидаемыми результатами;
- оформить чек-лист регрессионной проверки;
- связать тест-кейсы с требованиями технического задания.

**Проектный контекст.** Работа выполняется на материале сквозного проекта «Мафия». Проверяются ключевые модули: раздача ролей, игровой цикл, голосование.

## 2. Теоретические сведения

**Тестирование** — процесс выполнения программы с целью обнаружения ошибок.
**Отладка** — локализация и устранение найденных ошибок.

**Уровни тестирования:**

| Уровень | Что проверяется |
|---|---|
| Модульное | отдельная функция или класс |
| Интеграционное | взаимодействие модулей |
| Системное | продукт целиком |
| Приёмочное | соответствие требованиям заказчика |

**Виды тестирования по доступу к коду:** «белый ящик» (код известен), «чёрный ящик» (проверка по требованиям), «серый ящик» (частично).

**Структура тест-кейса:**

| Поле | Содержание |
|---|---|
| Идентификатор | TC-01 |
| Название | Проверка раздачи ролей на 8 игроков |
| Предусловие | комната создана, 8 игроков подключены |
| Шаги | 1. Ведущий нажимает «Раздать роли». 2. … |
| Ожидаемый результат | каждому игроку выдана одна роль, состав соответствует настройкам |
| Постусловие | партия в состоянии «Ночь» |
| Связанное требование | ТЗ, п. 4.1, модуль М2 |

**Техники проектирования тестов:**

- **классы эквивалентности** — входные данные делятся на группы, внутри которых поведение одинаково; достаточно проверить по одному представителю;
- **граничные значения** — проверяются значения на границах диапазонов (минимум, минимум−1, максимум, максимум+1);
- **попарное тестирование** — комбинации параметров покрываются парами.

**Чек-лист** — короткий перечень проверок без детальных шагов. Используется для регрессии, когда важна скорость, а не протоколирование.

## 4. Порядок выполнения

### Шаг 1. Определить объекты тестирования

- Выбрать 3 модуля для проверки: **раздача ролей**, **игровой цикл**, **голосование**.
- Для каждого выписать функции, подлежащие проверке.
- **Результат:** перечень объектов тестирования.

### Шаг 2. Выделить классы эквивалентности

- Для каждой функции определить входные параметры и разбить их значения на классы.
- Пример для числа игроков: допустимо 4–20; классы — «меньше 4», «4–20», «больше 20».
- **Результат:** таблица классов эквивалентности.

### Шаг 3. Определить граничные значения

- Для каждого диапазона указать границы и значения рядом с ними.
- Пример: 3 игрока (недопустимо), 4 игрока (минимум), 20 игроков (максимум), 21 игрок (недопустимо).
- **Результат:** перечень граничных значений.

### Шаг 4. Составить тест-кейсы

- Оформить 15–20 тест-кейсов по структуре из раздела 2.
- Обязательно включить: позитивные сценарии, негативные сценарии, граничные значения.
- Для каждого указать связанное требование ТЗ.
- **Результат:** таблица тест-кейсов.

### Шаг 5. Составить чек-лист регресса

- Перечислить 10–15 коротких проверок, которые нужно повторять после каждого изменения: вход в комнату, раздача ролей, смена фаз, голосование, подсчёт.
- **Результат:** чек-лист готов.

### Шаг 6. Проверить покрытие

- Сверить: каждая функция из шага 1 покрыта хотя бы одним тест-кейсом.
- Посчитать, сколько классов эквивалентности задействовано.
- **Результат:** таблица покрытия.

### Шаг 7. Оформить пояснительную записку

- Описать, что тестировалось, какие техники применялись, что осталось непокрытым.
- **Результат:** записка приложена к отчёту.

## 7. Критерии оценки

| Критерий | 2 | 3 | 4 | 5 |
|---|---|---|---|---|
| Объекты тестирования | не определены | 1–2 модуля | 3 модуля | + обоснован выбор |
| Классы эквивалентности | нет | частично | выделены | + граничные значения |
| Число тест-кейсов | <8 | 8–14 | 15–20 | + связь с требованиями |
| Негативные сценарии | отсутствуют | 1–2 | 4–5 | + граничные и негативные вместе |
| Чек-лист регресса | нет | <8 пунктов | 10–15 пунктов | + порядок выполнения |

Оценка выставляется по формуле: 60 % командный результат + 40 % личный вклад.
