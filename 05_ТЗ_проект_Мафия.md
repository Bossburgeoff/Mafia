## 1. Введение

**1.1. Наименование программы.** Приложение для проведения игры «Мафия».

**1.2. Условное обозначение.** Mafia-2026.

**1.3. Область применения.** Учебный проект по МДК 02.01 «Моделирование и анализ ПО» и МДК 02.02 «Управление проектами». Продукт предназначен для ведения партии игры «Мафия» в учебной аудитории: ведущий работает за компьютером, игроки подключаются со своих устройств.

## 3. Назначение разработки

**3.1. Функциональное назначение.** Автоматизация ведения партии игры «Мафия»: раздача ролей, управление фазами, подсчёт голосов, ведение журнала и статистики.

**3.2. Эксплуатационное назначение.** Использование в учебных группах, студенческих клубах, на внеаудиторных мероприятиях. Ведущий — один человек, игроков — от 4 до 20.

**3.3. Что программой не является.** Продукт не заменяет игру и не ведёт её за игроков: он снимает с ведущего механическую работу (учёт ролей, подсчёт голосов, отслеживание фаз), оставляя ему содержательное ведение партии.

## 4. Требования к программе

### 4.1. Требования к функциональным характеристикам

| Модуль | Функции | Требования |
|---|---|---|
| **М1. Лобби** | создание комнаты, подключение игроков, список участников | Код подключения из 4–6 символов; до 20 игроков; отображение статуса подключения; выход и повторный вход игрока |
| **М2. Роли** | состав ролей, случайная раздача, приватный показ | Набор: Мирный житель, Мафия, Комиссар, Доктор, Дон; количество ролей настраивается под число игроков; карточка роли видна только её владельцу; повторная раздача запрещена |
| **М3. Игровой цикл** | фазы «ночь» и «день», таймеры, переходы | Автоматическая смена фаз; настраиваемая длительность фаз; индикация текущей фазы у всех участников; пауза и возобновление |
| **М4. Голосование** | выдвижение, голосование, подсчёт, казнь | Голосование днём; подсчёт в реальном времени; обработка ничьей; запрет повторного голоса; журналирование результатов |
| **М5. Панель ведущего** | управление партией, ручные корректировки | Запуск и завершение партии; принудительная смена фазы; ручная правка статуса игрока; просмотр полного состояния партии |
| **М6. Журнал и статистика** | история партий, статистика игроков, экспорт | Хранение истории партий; статистика по игрокам (партии, победы, роли); экспорт в CSV |
| **М7. Коммуникации** | уведомления, чат, сигналы | Уведомления о смене фаз; общий чат комнаты; звуковой сигнал начала ночи и голосования |

### 4.2. Требования к надёжности

| Требование | Значение |
|---|---|
| Одновременные подключения | не менее 20 без потери отклика |
| Разрыв связи у игрока | партия продолжается; игрок возвращается без потери статуса |
| Восстановление партии | после перезапуска сервера состояние последней партии восстанавливается |
| Сохранность данных | журнал партий не теряется при аварийном завершении |
| Целостность данных | невозможны два голоса от одного игрока в одном раунде |

### 4.3. Условия эксплуатации

Локальная сеть учебной аудитории. Специальных требований к квалификации ведущего не предъявляется: достаточно уверенного владения браузером. Обслуживающий персонал не требуется.

### 4.8. Специальные требования

1. Интерфейс полностью на русском языке.
2. Роль игрока не раскрывается другим участникам ни через интерфейс, ни через сетевой обмен.
3. Время отклика интерфейса на действие — не более 1 секунды.
4. Работа без доступа в интернет (только локальная сеть).
5. Оформление документации — по ГОСТ 19.201-78 и ГОСТ 19.402-78.

## 8. Порядок контроля и приёмки

**8.1. Текущий контроль** — по вехам:

| Веха | Что сдаётся |
|---|---|
| 1. Аналитика | ТЗ, ЛР1, ЛР2, ПР1, ПР2 |
| 2. Проектирование | ЛР3, ПР3, ПР4, ПР5 |
| 3. Разработка | ЛР4, ЛР5, ЛР6, ПР6, ПР7, ПР8, ПР9 |
| 4. Стабилизация | ЛР7, ЛР8, ЛР9, ПР10, ПР11, ПР12 |
| 5. Защита | ПР13 |

**8.2. Приёмочные испытания.** Не менее 10 партий полного цикла с разным числом игроков (от 4 до 20) и разными составами ролей. Результат — протокол приёмочного тестирования и журнал дефектов.

**8.3. Критерии приёмки:**
1. Все модули М1–М7 реализованы и работают.
2. Партия проходит полный цикл без вмешательства в код.
3. Выполнены требования раздела 4.2 (надёжность).
4. Комплект документации по разделу 5 сдан.
5. Дистрибутив устанавливается на чистую машину по инструкции.

**8.4. Оценка личного вклада.** Каждый участник защищает свой участок (5–7 минут). Оценка = 60 % командный результат + 40 % личный вклад.
