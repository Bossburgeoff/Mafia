## 1. Цель и задачи работы

**Цель:** освоить построение модели «сущность — связь» (ER-модели) для проектирования базы данных информационной системы.

**Задачи:**

- выделить сущности предметной области и их атрибуты;
- определить первичные и внешние ключи;
- установить связи между сущностями и их кардинальность;
- привести модель к третьей нормальной форме;
- сформировать DDL-скрипт создания базы данных.

**Проектный контекст.** Работа выполняется на материале сквозного проекта «Мафия». Модель описывает данные, с которыми работает приложение: игроки, комнаты, партии, роли, голоса, события.

## 2. Теоретические сведения

**ER-модель (Entity-Relationship)** — модель данных, описывающая предметную область через сущности, их атрибуты и связи между ними.

**Основные понятия:**

| Понятие | Определение |
|---|---|
| Сущность | объект предметной области, о котором хранятся данные (Игрок, Партия) |
| Атрибут | характеристика сущности (имя, дата, статус) |
| Первичный ключ (PK) | атрибут, однозначно определяющий экземпляр сущности |
| Внешний ключ (FK) | атрибут, ссылающийся на первичный ключ другой сущности |
| Связь | отношение между сущностями |

**Виды связей по кардинальности:**

- **один к одному (1:1)** — одной записи соответствует ровно одна;
- **один ко многим (1:N)** — одной записи соответствует несколько;
- **многие ко многим (M:N)** — реализуется через промежуточную таблицу.

**Нормальные формы:**

1. **1НФ** — все атрибуты атомарны, нет повторяющихся групп.
2. **2НФ** — выполнена 1НФ, и каждый неключевой атрибут зависит от полного первичного ключа.
3. **3НФ** — выполнена 2НФ, и нет транзитивных зависимостей (неключевой атрибут не зависит от другого неключевого).

**Правило:** в учебном проекте достаточно третьей нормальной формы. Денормализация допускается только осознанно и с обоснованием.

## 4. Порядок выполнения

### Шаг 1. Выделить сущности

- Определить сущности предметной области: **Игрок**, **Комната**, **Партия**, **Роль**, **Голос**, **Событие**, **Сообщение**.
- Проверить, что каждая сущность — это объект, а не действие.
- **Результат:** перечень сущностей с кратким описанием.

### Шаг 2. Определить атрибуты

- Для каждой сущности выписать атрибуты. Пример для сущности «Игрок»: идентификатор, имя, дата регистрации, статус.
- Убедиться, что атрибуты атомарны (1НФ).
- **Результат:** таблица «Сущность — атрибуты».

### Шаг 3. Назначить ключи

- Для каждой сущности определить первичный ключ.
- Отметить внешние ключи (например, в «Голос» — ссылки на игрока и на партию).
- **Результат:** ключи отмечены на диаграмме.

### Шаг 4. Установить связи

- Определить связи и их кардинальность. Примеры:
  - Игрок **участвует** в Партии — M:N (через таблицу «Участник партии»);
  - Партия **содержит** Голоса — 1:N;
  - Игрок **имеет** Роль в партии — M:N;
  - Партия **состоит из** Событий — 1:N.
- **Результат:** диаграмма со связями.

### Шаг 5. Привести модель к третьей нормальной форме

- Проверить каждый атрибут: атомарен ли, зависит ли от полного ключа, нет ли транзитивных зависимостей.
- Исправить найденные нарушения, выписать их в записку.
- **Результат:** модель в 3НФ с описанием исправлений.

### Шаг 6. Составить DDL-скрипт

- Написать SQL-скрипт создания таблиц: `CREATE TABLE` с типами, первичными и внешними ключами.
- Выполнить скрипт в СУБД и убедиться, что таблицы создаются без ошибок.
- **Результат:** рабочий DDL-скрипт.

### Шаг 7. Оформить пояснительную записку

- Описать сущности, атрибуты, связи, принятые решения по нормализации.
- **Результат:** записка приложена к отчёту.

## 7. Критерии оценки

| Критерий | 2 | 3 | 4 | 5 |
|---|---|---|---|---|
| Полнота сущностей | <4 | 4–5 | 6–7 | 7 + обоснование состава |

| Связи и кардинальность | не показаны | с ошибками | верные | + обоснованы |
