## 1. Цель и задачи работы

**Задачи:**

## 2. Теоретические сведения

**UML (Unified Modeling Language)** — язык графического описания объектно-ориентированных систем.

**Основные виды диаграмм, применяемые в проекте:**

| Диаграмма | Что показывает | Где используется |
|---|---|---|
| Вариантов использования | что система делает для пользователя | постановка задач |
| Классов | структура: классы, атрибуты, методы, связи | проектирование кода |
| Последовательности | взаимодействие объектов во времени | проработка сценариев |
| Деятельности | поток управления с условиями | описание процессов |

**Элементы диаграммы классов:**

| Элемент | Обозначение | Пример |
|---|---|---|
| Класс | прямоугольник с тремя секциями | `Партия` |
| Атрибут | поле класса | `- датаНачала: Дата` |
| Метод | операция класса | `+ начать(): void` |
| Видимость | знак перед именем | `+` открытый, `-` закрытый, `#` защищённый |
| Ассоциация | простая линия | «Игрок — Партия» |
| Агрегация | линия с пустым ромбом | «Команда состоит из игроков» |
| Композиция | линия с закрашенным ромбом | «Партия состоит из раундов» |
| Наследование | линия со стрелкой-треугольником | «Дон — частный случай Мафии» |
| Зависимость | пунктирная стрелка | «Модуль использует журнал» |

**Кратность** указывается у концов связи: `1`, `0..1`, `1..*`, `*` (много).

**Диаграмма последовательности:** объекты располагаются сверху, время идёт вниз, сообщения — горизонтальные стрелки, активация — прямоугольник на линии жизни.

## 4. Порядок выполнения

### Шаг 1. Построить диаграмму вариантов использования

- Определить актёров: **Ведущий**, **Игрок**, **Администратор**.
- Для каждого актёра перечислить варианты использования (создать комнату, раздать роли, проголосовать, посмотреть статистику).
- Показать связи `include` и `extend` там, где они есть.
- **Результат:** диаграмма вариантов использования.

### Шаг 2. Выделить классы

- Перенести сущности из ER-модели и дополнить их классами логики: `Партия`, `Раунд`, `Игрок`, `Роль`, `Голосование`, `Журнал`, `Комната`.
- **Результат:** перечень классов с назначением.

### Шаг 3. Описать атрибуты и методы

- Для каждого класса указать 3–6 атрибутов с типами и 2–4 метода.
- Проставить видимость: закрытые атрибуты, открытые методы.
- **Результат:** классы описаны полностью.

### Шаг 4. Установить связи

- Определить тип каждой связи: ассоциация, агрегация, композиция, наследование, зависимость.
- Указать кратность на обоих концах.
- **Результат:** диаграмма классов со связями.

### Шаг 5. Построить диаграмму последовательности

- Выбрать сценарий «Фаза „Ночь“»: ведущий запускает фазу, мафия делает выбор, комиссар проверяет, система фиксирует результат.
- Показать объекты, сообщения и время жизни.
- **Результат:** диаграмма последовательности.

### Шаг 6. Проверить согласованность

- Сверить: все классы соответствуют сущностям ER-модели; каждый вариант использования обеспечен методами классов; на диаграмме последовательности используются только объявленные методы.
- **Результат:** список расхождений устранён.

### Шаг 7. Оформить пояснительную записку

- Описать принятые решения: почему выбраны такие классы, связи и кратности.
- **Результат:** записка приложена к отчёту.
