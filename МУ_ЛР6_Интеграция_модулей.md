## 1. Цель и задачи работы

**Цель:** освоить сборку отдельных модулей в единое работающее приложение.

**Задачи:**

- зафиксировать интерфейсы взаимодействия между модулями;
- определить порядок интеграции;
- собрать модули в единое приложение;
- проверить сквозной сценарий партии;
- оформить протокол интеграции.

**Проектный контекст.** Работа выполняется на материале сквозного проекта «Мафия». К этому моменту модули разработаны командами по отдельности; задача — заставить их работать вместе.

## 2. Теоретические сведения

**Интеграция** — объединение разработанных модулей в единый программный продукт с проверкой их совместной работы.

**Стратегии интеграции:**

| Стратегия | Порядок | Достоинство | Недостаток |
|---|---|---|---|
| Нисходящая | сначала верхние уровни, нижние заменяются заглушками | рано виден каркас системы | нужны заглушки |
| Восходящая | сначала нижние уровни, затем сборка | раньше проверяется логика | результат виден поздно |
| «Большой скачок» | все модули сразу | быстро | ошибки искать сложно |

**Заглушка (stub)** — упрощённая замена ещё не готового модуля, возвращающая заранее заданный результат.

**Интерфейс взаимодействия** — договорённость о том, как модули обращаются друг к другу: имя операции, входные параметры, возвращаемый результат, возможные ошибки.

**Признаки плохой интеграции:**

- модули «знают» о внутреннем устройстве друг друга;
- интерфейсы меняются без предупреждения;
- один модуль напрямую меняет данные другого в обход интерфейса.

**Правило:** сначала фиксируются интерфейсы — потом пишется код интеграции.

## 4. Порядок выполнения

### Шаг 1. Собрать перечень модулей

- Выписать модули, готовые к интеграции, и их состояние.
- Отметить, какие модули ещё не готовы и потребуют заглушек.
- **Результат:** таблица «Модуль — состояние — ответственный».

### Шаг 2. Зафиксировать интерфейсы

- Для каждой пары взаимодействующих модулей описать: имя операции, входные данные, результат, ошибки.
- Оформить в виде таблицы или спецификации API.
- **Результат:** спецификация интерфейсов.

### Шаг 3. Выбрать стратегию интеграции

- Определить порядок сборки (нисходящая, восходящая или комбинированная).
- Обосновать выбор.
- **Результат:** план интеграции с очерёдностью шагов.

### Шаг 4. Подготовить заглушки

- Для неготовых модулей написать заглушки, возвращающие ожидаемые данные.
- **Результат:** заглушки работают, приложение запускается.

### Шаг 5. Выполнить сборку

- Собрать модули в единое приложение по плану из шага 3.
- После каждого шага сборки запускать приложение и фиксировать состояние.
- **Результат:** приложение запускается целиком.

### Шаг 6. Проверить сквозной сценарий

- Пройти полный цикл: создание комнаты → подключение игроков → раздача ролей → фаза «Ночь» → фаза «День» → голосование → итог партии.
- Зафиксировать, на каком шаге возникают сбои.
- **Результат:** протокол сквозной проверки.

### Шаг 7. Оформить протокол интеграции

- Описать: что интегрировано, какие интерфейсы задействованы, какие заглушки остались, какие дефекты найдены.
- **Результат:** протокол приложен к отчёту.

## 5. Требования к отчёту

Отчёт содержит:

1. Титульный лист (дисциплина, работа, группа, ФИО, дата).
2. Цель работы.
3. Таблицу состояния модулей.
4. Спецификацию интерфейсов (имя операции, вход, результат, ошибки).
5. Обоснование выбранной стратегии интеграции.
6. Перечень использованных заглушек.
7. Протокол сквозной проверки с указанием пройденных и непройденных шагов.
8. Список найденных дефектов с приоритетами.
9. Заполненный чек-лист приёмки.
10. Вывод.

5. Почему опасно, когда модуль напрямую меняет данные другого в обход интерфейса?
6. Какие дефекты обычно проявляются только на этапе интеграции?
7. Как вы определите, что интеграция завершена?

## 7. Критерии оценки

| Критерий | 2 | 3 | 4 | 5 |
|---|---|---|---|---|
| Перечень модулей | нет | неполный | полный со состояниями | + ответственные |
| Интерфейсы | не описаны | частично | описаны все | + обработка ошибок |
| Стратегия интеграции | не выбрана | выбрана без обоснования | обоснована | + план по шагам |
| Сборка | не запускается | запускается с ошибками | запускается | + сквозной сценарий |
| Протокол интеграции | нет | формальный | с дефектами | + приоритеты и сроки |

Оценка выставляется по формуле: 60 % командный результат + 40 % личный вклад.
