**Задачи:**

## 2. Теоретические сведения

**Приёмочное тестирование** — проверка готового продукта на соответствие требованиям заказчика, по результатам которой принимается решение о готовности.

**Программа и методика испытаний (ПМИ)** — документ, определяющий, что, как и в каком порядке проверяется. Оформляется по ГОСТ 19.301-79.

**Состав ПМИ:**

| Раздел | Содержание |
|---|---|
| Объект испытаний | что проверяется, версия |
| Цель испытаний | что должно быть подтверждено |
| Требования к объекту | ссылки на пункты ТЗ |
| Условия испытаний | оборудование, состав данных |
| Порядок проведения | последовательность проверок |
| Методы испытаний | как именно проверяется |
| Критерии приёмки | при каких результатах продукт принимается |

**Журнал дефектов** — таблица найденных проблем со статусами. Обязательные поля:

| Поле | Содержание |
|---|---|
| Идентификатор | BUG-01 |
| Описание | что произошло |
| Шаги воспроизведения | как повторить |
| Ожидаемый результат | что должно быть |
| Фактический результат | что получилось |
| Приоритет | блокирующий / высокий / средний / низкий |
| Статус | открыт / в работе / исправлен / закрыт |

**Приоритеты дефектов:**

- **блокирующий** — продукт нельзя использовать;
- **высокий** — основная функция не работает;
- **средний** — функция работает с ограничениями;
- **низкий** — косметический недостаток.

**Критерии приёмки** из технического задания: реализованы все семь модулей, партия проходит полный цикл без вмешательства в код, выполнены требования к надёжности (20 одновременных подключений, восстановление партии), документация сдана, дистрибутив устанавливается по инструкции.

## 4. Порядок выполнения

### Шаг 1. Разработать программу и методику испытаний

- Оформить ПМИ по структуре из раздела 2.
- Указать ссылки на пункты технического задания.
- **Результат:** документ ПМИ.

### Шаг 2. Подготовить условия испытаний

- Определить состав данных: число игроков, набор ролей, длительность фаз.
- Подготовить не менее трёх вариантов состава: минимальный (4 игрока), средний (10), максимальный (20).
- **Результат:** план испытаний.

### Шаг 3. Провести испытания

- Провести не менее 10 партий полного цикла.
- Обязательно охватить: минимальный и максимальный состав, ничью при голосовании, разрыв соединения у игрока, перезапуск сервера в середине партии.
- После каждой партии фиксировать результат.
- **Результат:** протокол по каждой партии.

### Шаг 4. Вести журнал дефектов

- Заносить каждый дефект с шагами воспроизведения и приоритетом.
- Отмечать статус: исправлен или остаётся открытым.
- **Результат:** журнал дефектов.

### Шаг 5. Сопоставить результаты с критериями приёмки

- Пройти по пунктам раздела 8 технического задания.
- Для каждого указать: подтверждён или нет, чем подтверждён.
- **Результат:** таблица соответствия критериям приёмки.

### Шаг 6. Оформить протокол испытаний

- Описать: объект, условия, ход, результаты, открытые дефекты, вывод о готовности.
- **Результат:** протокол приложен к отчёту.

### Шаг 7. Сдать документацию

- Проверить комплектность: ТЗ, схема БД, описание программы, руководства пользователя и по установке, ПМИ, реестр документов.
- **Результат:** комплект документов сдан.

7. Таблицу соответствия критериям приёмки из ТЗ.
8. Перечень открытых дефектов с оценкой влияния.
9. Заполненный чек-лист приёмки.
10. Вывод о готовности продукта.

## 7. Критерии оценки

| Критерий | 2 | 3 | 4 | 5 |
|---|---|---|---|---|
| ПМИ | нет | схематичный | полный по ГОСТ 19.301-79 | + связь с пунктами ТЗ |
| Число партий | <5 | 5–9 | 10+ | + разные составы и сценарии |
| Журнал дефектов | нет | без приоритетов | полный | + статусы и шаги воспроизведения |
| Соответствие критериям приёмки | не проверено | частично | по всем пунктам | + обоснование выводов |
| Протокол испытаний | нет | формальный | полный | + вывод о готовности |

Оценка выставляется по формуле: 60 % командный результат + 40 % личный вклад.
